## 二、完整数据流

### 一次完整的调用链路

```
用户上传小票照片
    │
    ▼
POST /api/v1/calls/prepare
    │
    ▼
ContextPreparationWorkflow.execute(photoBase64)
    │
    ├── [1] OrderNode
    │     └─ RealOrderUnderstandingService
    │           └─ JDK HttpClient → OpenRouter (qwen3.6-plus)
    │                 → 识别出：餐厅名、菜品、数量、时间等
    │                 → 返回 OrderData
    │
    ├── [2] DishNode
    │     └─ DishRetriever.retrieve(["打抛饭","鱿鱼船粉",...])
    │           └─ HashMap 精确匹配 115 道菜品知识
    │                 → 返回 List<DishKnowledge>
    │
    ├── [3] RealtimeNode
    │     ├─ RestaurantRepository.findByName("壳泰·泰式船粉")
    │     │     → 模糊匹配到 "売泰" → 地址 "北京市朝阳区三里屯..."
    │     │     → 提取城市 "北京" + 区 "朝阳区"
    │     ├─ WeatherTool.getDistrictWeather("朝阳区", "北京")
    │     │     → JDK HttpClient → 高德地图 API
    │     │     → "北京：多云 31°C 西南风≤3级"
    │     │     （高德失败时自动降级到 wttr.in）
    │     ├─ LocalDateTime.now() → "星期二 16:15"
    │     └─ timor.tech 节假日 API → 非节日返回 null
    │           → 返回 RealtimeInfo
    │
    ├── [4] ExperienceNode
    │     └─ ExperienceUnderstandingAgent.analyze(order, dishes, realtime)
    │           └─ AiServices 代理 → DeepSeek API
    │                 → 返回 3~4 条体验可能性（保持低确定性）
    │
    ├── [5] PlannerNode
    │     └─ ConversationPlannerAgent.plan(order, dishes, realtime, experience)
    │           └─ AiServices 代理 → DeepSeek API
    │                 → 返回方向 / 机会点 / 限制
    │
    └── [6] AssemblyNode
          ├─ ContextAssembler.assemble(ctx)
          │     → 三层纯文本：Raw Facts + 体验理解 + 对话策略
          └─ PromptAssembler.assemble(ctx)
                → Static System Prompt + Dynamic Context
                → 最终 Runtime Prompt（约 4700 字符）
```

## 三、完整文件清单（33 个 Java 文件）

### 3.1 启动类

| 文件 | 说明 |
|---|---|
| `MokaApplication.java` | Spring Boot 启动入口 |

### 3.2 AI 层 — Agent（5 个）

| 文件 | 说明 |
|---|---|
| `OrderUnderstandingService.java` | 订单理解服务接口 |
| `MockOrderUnderstandingService.java` | Mock 实现（`mock=true`），返回预设数据 |
| `RealOrderUnderstandingService.java` | 真实实现（`mock=false`），调用 OpenRouter 视觉 API |
| `ExperienceUnderstandingAgent.java` | 体验理解 Agent 接口（`@SystemMessage` + `@UserMessage`） |
| `ConversationPlannerAgent.java` | 对话规划 Agent 接口（`@SystemMessage` + `@UserMessage`） |

### 3.3 AI 层 — 数据模型（13 个）

| 类别 | 文件 | 说明 |
|---|---|---|
| Layer 1 | `OrderData.java` | 订单解析结果 |
| | `DishItem.java` | 单道菜品完整信息（数量、辣度、备注） |
| | `RestaurantProfile.java` | 餐厅基本信息（含地址） |
| | `DishKnowledge.java` | 菜品知识（含 dishRole） |
| | `DishRole.java` | 菜品角色枚举 |
| | `RealtimeInfo.java` | 实时信息（天气/时间/节日） |
| Layer 2 | `ExperienceUnderstanding.java` | 体验理解输出（List of possibilities） |
| | `ExperiencePossibility.java` | 单条体验可能性 |
| | `ConfidenceLevel.java` | 确定性枚举（LOW / MEDIUM） |
| Layer 3 | `ConversationPlan.java` | 对话策略输出 |
| 上下层 | `WorkflowContext.java` | 工作流上下文（所有 Agent 间传递数据） |
| | `RuntimePrompt.java` | 最终 Runtime Prompt 封装 |
| 组装 | `ContextAssembler.java` | 三层文本组装器 |

### 3.4 AI 层 — Workflow（4 个）

| 文件 | 说明 |
|---|---|
| `WorkflowNode.java` | Node 接口 |
| `ContextPreparationWorkflow.java` | 6 步 Pipeline 编排引擎 |
| `ContextPreparationDemo.java` | Mock 模式启动验证 |
| `WorkflowExecutionException.java` | Workflow 执行异常 |

### 3.5 AI 层 — 检索（2 个）

| 文件 | 说明 |
|---|---|
| `DishRetriever.java` | 菜品知识 HashMap 精确匹配 |
| `RestaurantRepository.java` | 餐厅信息模糊匹配 |

### 3.6 AI 层 — 工具（1 个）

| 文件 | 说明 |
|---|---|
| `WeatherTool.java` | 高德天气 API + wttr.in fallback |

### 3.7 AI 层 — Prompt（2 个）

| 文件 | 说明 |
|---|---|
| `SystemPromptLoader.java` | Static System Prompt 加载器 |
| `PromptAssembler.java` | System Prompt + Dynamic Context 合并 |

### 3.8 业务层 — Controller（2 个）

| 文件 | 说明 |
|---|---|
| `OrderController.java` | `POST /api/v1/orders/upload-photo` → 解析小票 |
| `CallController.java` | `POST /api/v1/calls/preview` + `/prepare` → 完整 Pipeline |

### 3.9 通用配置层（3 个）

| 文件 | 说明 |
|---|---|
| `LangChain4jConfig.java` | DeepSeek 语言模型 + OpenRouter 视觉模型双配置 |
| `AiServiceConfig.java` | `mock=false` 时创建 AI 代理 |
| `MockLlmService.java` | `mock=true` 时提供预设数据 |

## 四、外部服务清单

| 服务 | 用途 | 是否需要 Key | 免费额度 |
|---|---|---|---|
| **DeepSeek API**（直连） | 文本推理（体验理解 + 对话规划） | ✅ 需要 | 按量计费 |
| **OpenRouter API** | 视觉模型（小票 OCR） | ✅ 需要 | 按量计费 |
| **高德地图 API** | 区级天气查询 | ✅ 需要 | 30 万次/日 |
| **timor.tech 节假日 API** | 节假日判断 | ❌ 不需要 | 无限制 |
| **wttr.in** | 天气 fallback | ❌ 不需要 | 无限制 |

## 五、两种启动模式对比

| 对比项 | Mock 模式 | Real 模式 |
|---|---|---|
| **启动命令** | `mvn spring-boot:run` | `mvn spring-boot:run -Dspring-boot.run.arguments="--moka.llm.mock=false"` |
| **启动时间** | ~3 秒 | ~13 秒（含 AI 调用） |
| **订单数据** | MockLlmService 预设 | 视觉 LLM 识别真实小票 ✅ |
| **菜品知识** | 真实 115 道菜数据 ✅ | 真实 115 道菜数据 ✅ |
| **天气** | 预设值 | 高德 API 真实天气 ✅ |
| **AI 推理** | MockLlmService 预设 | 真实 DeepSeek 调用 ✅ |
| **网络依赖** | ❌ 不需要 | ✅ 需要 |
| **API Key** | ❌ 不需要 | ✅ 需要配置 |
| **启动验证** | ContextPreparationDemo | CallController `/preview` |
