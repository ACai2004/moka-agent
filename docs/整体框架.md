# 摩卡餐后漫谈 AI Voice Agent 系统技术实现说明

## 1. 项目背景与目标

本项目目标是构建一个面向多餐厅场景的 AI 餐后漫谈 Voice Agent 系统。

不同于传统满意度调查机器人，本系统希望通过电话形式：

- 帮助用户重新回忆本次用餐体验；
- 理解用户本次用餐背景；
- 根据餐厅特点、订单信息和实时环境生成个性化聊天上下文；
- 在实时通话中进行自然交流。

核心目标：

> 从“收集用户反馈”升级为“理解用户体验，并陪伴用户回味这顿饭”。

系统最终希望实现：

用户离店后，通过 AI 电话与用户进行自然交流。

AI 不应该像问卷系统一样询问：

- 菜好不好吃？
- 满不满意？
- 服务怎么样？

而应该像一个了解场景的体验伙伴：

- 帮助用户回忆刚刚发生的事情；
- 根据用户兴趣自然展开交流；
- 让用户感受到自己的体验被认真倾听。

## 系统边界说明（非常重要）

本项目不会实现 Voice Agent 本身。

火山引擎负责：

- ASR（语音识别）
- TTS（语音合成）
- 实时电话连接
- 实时语音对话能力
- Voice Agent运行环境


本项目负责：

- 通话前的数据准备；
- 用户和餐厅业务数据管理；
- AI Context生成；
- Agent Workflow编排；
- RAG和Tool能力；
- 将生成的 Context 对接给火山 Voice Agent。


因此：

Claude Code 不需要实现：

- ASR模块
- TTS模块
- 电话系统
- Voice Runtime
- 语音模型


只需要预留未来与火山引擎 Voice Agent 对接的接口。

# 3. 当前开发重点

当前阶段主要实现：

## AI Context Preparation Backend

目标：

在用户接听电话之前，根据已有信息生成：

```

Pre-call Context

```

供火山 Voice Agent 在实时通话中使用。


原因：

实时电话场景对于延迟敏感。

如果在通话过程中：

- 查询数据库；
- 检索知识库；
- 调用多个Agent；
- 进行复杂推理；

会影响用户体验。


因此采用：

```

通话前复杂处理

*

通话中低延迟交流

```

的设计。

# 6. Dish Knowledge Base（菜品知识库）

菜品信息使用 RAG。

原因：

不同餐厅菜品数量较多。

每道菜包含：

* 菜品介绍
* 制作方式
* 口味特点
* 用户可能体验
* 推荐聊天方向

例如：

```json
{
"dish":"麻婆豆腐",

"features":[
"经典川菜",
"家常风",
"麻辣香"
],

"experience_tags":[
"下饭",
"熟悉感",
"川味代表"
]

}

```

检索结果用于帮助 AI 理解：

用户点的菜可能具有什么体验特点。

注意：

知识库只是提供背景信息。

不能直接让 AI 假设用户一定喜欢某道菜。

# 9. Experience Understanding Module

作用：

根据已有信息推测：

“这顿饭可能是什么样的体验场景”。

输入：

* 订单
* 餐厅特点
* 时间
* 天气
* 人数

输出：

体验线索。

例如：

正确：

```
可能是一场节日晚餐

可能存在多人交流场景

```

错误：

```
用户一定是家庭聚餐

用户一定很开心

```

所有推测必须保持不确定性。

# 10. Conversation Planner

这是 AI Context Preparation 的核心模块。

原因：

前面的模块产生的是：

数据。

但是 Voice Agent 需要：

如何使用这些数据。

输入：

```
订单信息

餐厅特点

实时信息

体验线索

System Prompt原则

```

输出：

Conversation Context。

例如：

```json
{
"opening_strategy":

"不要直接询问菜品，可以从离店后的整体感受切入",


"conversation_hooks":[

"今天天气",

"用餐时间较长",

"多人聚餐场景"

],


"avoid":[

"不要假设同行关系",

"不要问卷式提问"

]

}

```

# 11. System Prompt 与 Context 的关系

System Prompt：

负责稳定能力：

* AI角色定义
* 对话原则
* 用户尊崇感
* 回复风格
* 禁止行为

Pre-call Context：

负责动态信息：

* 本次订单
* 本次餐厅
* 本次实时环境
* 本次聊天策略

二者结合：

```
System Prompt

+

Pre-call Context

↓

Voice Agent Conversation

```

Response:

{

# 14. 开发目标总结

当前代码重点：

实现一个：

基于 Spring Boot + Spring AI 的餐后漫谈 AI Context Preparation Platform。

核心能力：

* 多餐厅数据管理
* 订单解析
* 菜品RAG
* Tool Calling
* Experience Reasoning
* Conversation Planning
* Pre-call Context生成

不实现：

* 语音识别
* 语音合成
* 电话系统
* Voice Agent运行环境

最终目标：

让火山 Voice Agent 在实时通话时拥有更加丰富、个性化、自然的人类交流能力。
